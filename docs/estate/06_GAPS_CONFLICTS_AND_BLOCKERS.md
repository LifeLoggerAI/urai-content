# Contradictions, security findings and release HOLD gates
1. **Firebase rules divergence — P0:** root `firestore.rules` includes bounded analytics, free marketplace/public content predicates and creator roles; `apps/web/firestore.rules` uses a simpler telemetry authenticated-create policy and broader global template reads. Root `storage.rules` restricts creator files to <=25 MiB allowed MIME and roles; `apps/web/storage.rules` has owner write without corresponding size/MIME rule. Different firebase.json roots select different rules. **Which one is deployed is unknown.** Confirm environment/project, exact effective rules, emulator cross-user tests and secure Admin IAM.
2. **Main session admission — P0:** main `apps/web/src/server/auth/session.ts` allows production header auth when `URAI_ENABLE_HEADER_AUTH=1` and calls `verifyIdToken(token)` without revocation parameter; #96 disables header auth in production, verifies token revocation/current roles, checks canonical Privacy C1/C7 at private consumer routes. No live exploit or production fix is asserted.
3. **Protected private text — P0:** creator intake may contain personal stories in `body`, up to 20k characters. Main route does not consult current canonical Privacy consent; #96 checks memory.storage and data.export but is not production-bound. Personal memory/media must stay private until consent, owner authority, deletion and sharing verified.
4. **Non-atomic writes — P0:** root content upsert/version/release log and admin moderation+queue log are separate writes. Failure/race/compensating semantics and current-role recheck needed. #96 changes require independent real emulators.
5. **Public unlisted — P0:** `runtimeCatalog.ts` combines published public+unlisted in Firestore mode. Investigate search/SEO/share discoverability before live promotion.
6. **Analytics and PII — P0:** `src/telemetry/policy.ts` has a strict metadata allowlist, but public `/api/analytics` accepts generic scalar property keys and stores referer/user-agent. `/api/leads` can store email/name/message and returns `ok:true stored:false` preview when Firebase missing; does not certify durable ingestion. Audit data rights/marketing consent/retention.
7. **Publication authority — P0:** main receipt evaluates metadata only; #110/#111 strengthen claims and signed Google issuer but cannot authenticate real IAM/approval in current observed cloud.
8. **Export/incomplete deletion — P0:** #96 own-data export has partial 6 scopes, a six-collection unmapped list and hard limits, not a whole account export. Source tombstone/Purge receipt does not delete storage objects itself.
9. **Provider deployment and source parity — P0:** Vercel is ERROR; #112 root and compiled SHA checks are unmerged guards, not a repair confirmed in deployed runtime.
10. **Data/media/localization — P1:** missing binary assets, rights approvals, real native translations, final captions/alt/XR acceptance, provider-generated outputs and legal signoffs.
11. **History and workers — P2:** 2024–2025 full object history, LFS and other account/Firebase/Drive sources not exhaustively inspected.

Until each applicable denial/approval/real deployment gate is evidenced at the *same reviewed candidate SHA*, **NO-GO / HOLD**.
